# Problem Statement
Design, develop, deploy and evaluate a cloud-based application for 'Serverless Document Processing Workflow'. Automatically validate, process, classify and store uploaded documents through multiple processing stages with retry handling. The project must demonstrate cloud-specific behaviour rather than only basic CRUD operations.

------

## Project-Specific Requirements
- Implement the core functionality described in the assigned project: Automatically validate, process, classify and store uploaded documents through multiple processing stages with retry handling.
- Design at least 5 meaningful REST API endpoints related to this project.
- Design a proper data model for the main entities used in this project.
- Implement authentication/authorization suitable for the users or services involved.
- Deploy the application or its major components on a cloud/deployable environment.
- Maintain logs for important events, failures and user/service actions.
- Measure at least 2 project-relevant metrics and include results in the report.
- Perform load testing at low, medium and high workload levels.
- Create a cloud architecture diagram showing APIs, services, database, queues/cache/storage and users.
- Prepare API documentation and a final project report with screenshots and experimental results.
- Model the application around events such as upload, status change, sensor update, request submission or alert generation.
- Use asynchronous processing through queue, event trigger, workflow or simulated serverless functions.
- Handle duplicate, failed or delayed events wherever relevant.
- Maintain event history and final processed state.
- Demonstrate that one failed event does not block the entire system.

### Mandatory Demonstration

During evaluation, the student must demonstrate the working project 'Serverless Document Processing Workflow'. Demonstrate event generation, asynchronous processing and correct final state even when duplicate/failed/delayed events occur. The demo must include API execution, database/storage state, logs/metrics and explanation of the cloud architecture.

### Common Minimum Requirements
- Minimum 5 meaningful REST API endpoints.
- Use a database and justify SQL/NoSQL/cloud database selection.
- Implement authentication or authorization such as JWT, OAuth, API keys or RBAC.
- Use at least 3 meaningful cloud/architectural components.
- Implement one controlled failure scenario and explain the recovery/failure-handling mechanism.
- Perform load/scalability testing at minimum three workload levels.
- Maintain application logs and at least 2 measurable metrics.
- Prepare a clear cloud architecture diagram.
- Submit source code and a Git repository with at least 8 meaningful commits.
- Submit API documentation, screenshots, performance results, failure experiment and final report.
Attend individual viva and be ready for a live modification.
